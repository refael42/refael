# מדריך העלאה לחנויות — צעד אחרי צעד

המדריך כתוב למי שמעלה אפליקציה בפעם הראשונה. **כל מה שבתיבות האפורות מקלידים במחשב** (בחלון
הפקודות, בתיקיית הפרויקט). איפה שכתוב "לוחצים" — זה באתר.

> ⚠️ את השלבים עם חשבונות ותשלום רק אתה יכול לעשות: אני לא פותח חשבונות ולא מכניס פרטים אמיתיים.

## שלב 0 — החלטות (נעשו)
1. **שם האפליקציה:** שף טייקון / Chef Tycoon (כבר ב-`app.json`, בטקסטים ובמדיניות הפרטיות).
2. **מזהה האפליקציה** (bundle id): `com.refael.cheftycoon`. **אחרי ההעלאה הראשונה אי אפשר לשנות אותו.**
3. **אייפד:** כן (`supportsTablet: true` ב-`app.json`).
4. **חנויות:** Google Play ו-App Store ביחד.
5. **מייל לתמיכה:** `cheftycoon.support@gmail.com` (במסך הפרטיות במשחק, ב-`src/data/contact.ts` ובמדיניות הפרטיות). אותו מייל ממלאים בחנויות, ואפשר לפתוח איתו גם את חשבונות המפתח.

## שלב 1 — חשבונות מפתח (פעם אחת)
1. **Apple:** הכי קל מהאייפון: מורידים את האפליקציה **Apple Developer** ← Account ← Enroll Now (או באתר developer.apple.com). נרשמים כ-**Individual** (אדם פרטי; השם שלך יופיע בחנות כמוכר). צריך Apple ID עם אימות דו-שלבי ותעודה מזהה. 99$ לשנה. האישור לוקח בין שעה לכמה ימים.
2. **Google:** נכנסים ל-play.google.com/console ← נרשמים (25$ פעם אחת). חשבון אישי חדש צריך **בדיקה סגורה של 14 יום עם לפחות 12 בודקים** לפני שמותר לפרסם לכולם.
3. **Expo:** נכנסים ל-expo.dev ← Sign up (חינם). זה השירות שבונה את האפליקציה בענן.

## שלב 2 — חיבור הפרויקט ל-Expo (פעם אחת)
```
npm install -g eas-cli
eas login
eas init
```
`eas init` שואל אם ליצור פרויקט — עונים Yes. הוא מוסיף מזהה פרויקט ל-`app.json`.

**נעשה:** הפרויקט ב-Expo הוא `@refael42/restaurant-tycoon` (השם הפנימי ב-expo.dev; השחקנים רואים "Chef Tycoon"), והמזהה שלו כבר ב-`app.json`, כולל הכתובת לעדכונים המהירים. בהורדה חדשה של ה-ZIP לא צריך להריץ שוב `eas init` או `eas update:configure`, רק `eas login` פעם אחת במחשב.

ומיד אחריו (פעם אחת), כדי שאפשר יהיה לשלוח עדכונים מהירים בהמשך (שלב 11):
```
eas update:configure
```

## שלב 3 — בנייה ראשונה לבדיקה על הטלפון
- **אנדרואיד (הכי מהיר):** לחיצה כפולה על `build-android-test.bat` בתיקיית המשחק (או `eas build --profile preview --platform android`).
  בסוף מקבלים קישור לקובץ APK. פותחים אותו בטלפון ומתקינים.
- **אייפון:** צריך קודם את חשבון Apple. אחר כך:
  ```
  eas build --profile development --platform ios
  ```
  EAS ידריך לרשום את האייפון (סורקים קוד QR).

כאן בודקים: שהמשחק עולה, שהשמירה עובדת אחרי סגירה ופתיחה, ושהקנייה **לא** עובדת עדיין (אין מוצרים בחנות) ומציגה הודעה מסודרת.

## שלב 5 — יצירת האפליקציה בחנויות
- **App Store Connect** (appstoreconnect.apple.com) ← My Apps ← ➕ ← New App: פלטפורמה iOS, שם, שפה ראשית (עברית או אנגלית), Bundle ID `com.refael.cheftycoon`, SKU (כל מילה, למשל `cheftycoon1`). **המזהה מופיע ברשימה רק אחרי הבנייה הראשונה לאייפון** (`eas build` רושם אותו לבד), לכן באפל עושים קודם את הבנייה משלב 8 ואז את זה.
- **Google Play Console** ← Create app: שם, שפה, Game, Free.

- **אירופה (DSA):** שתי החנויות שואלות אם אתה "סוחר" (Trader). מי שמוכר בתוך המשחק הוא בדרך כלל סוחר, ואז באירופה מוצגים כתובת, טלפון ומייל. מי שלא רוצה להצהיר יכול להוריד את מדינות האיחוד מרשימת המדינות.

## שלב 8 — בנייה לחנות ושליחה
```
eas build --profile production --platform all
eas submit --platform ios
eas submit --platform android
```
בפעם הראשונה `eas build` לאייפון מבקש להתחבר עם ה-Apple ID ויוצר לבד את התעודות (עונים Yes לכל השאלות). הבנייה בענן לוקחת בערך 15–30 דקות. `eas submit` מעלה אותה ל-App Store Connect, ואחרי כרבע שעה עד שעה של עיבוד היא מופיעה ב-**TestFlight**: מתקינים באייפון את האפליקציה TestFlight, מוסיפים את עצמך כבודק פנימי (App Store Connect ← TestFlight ← Internal Testing), ומשחקים בגרסה האמיתית לפני כולם.

גרסת `production` היא הגרסה לחנויות: בלי כלי הבדיקה (כסף לבדיקה, אוטובוס לבדיקה, מד מהירות) ובלי כפתור הפרסומת לדוגמה.

## שלב 9 — בדיקת קנייה אמיתית (לפני שמפרסמים)
- **Apple:** App Store Connect ← Users and Access ← Sandbox ← יוצרים "בודק" (מייל בדיקה). בטלפון: הגדרות ← App Store ← Sandbox Account. קונים במשחק — לא יורד כסף אמיתי.
- **Google:** Play Console ← Setup ← License testing ← מוסיפים את המייל שלך. מעלים לגרסת Internal testing וקונים — לא יורד כסף.

בודקים: היהלומים מתווספים פעם אחת בלבד, וקנייה שבוטלה לא מוסיפה כלום.

## שלב 10 — שליחה לבדיקה
- Apple: בעמוד הגרסה ← Add for Review ← Submit. בדרך כלל 1–3 ימים.
- Google: Production ← Create release ← Review. (בחשבון אישי חדש — אחרי 14 יום של בדיקה סגורה.)

## שלב 11 — עדכונים אחרי שהמשחק בחנות
יש שני סוגים של עדכון:

**א. עדכון מהיר (רוב העדכונים):** תיקוני באגים, תוכן חדש, איזון, טקסטים, ציורים. לא צריך אישור של החנות, והשחקנים מקבלים אותו בפעם הבאה שהם פותחים את המשחק.
```
npm run release:check
eas update --channel production --message "מה השתנה"
```
`release:check` בודק שהכול תקין לפני (הקוד, הבדיקות והטקסטים לחנות). אם הוא נכשל — לא שולחים.

**ב. גרסה חדשה בחנות:** רק כשמוסיפים חבילה חדשה שצריכה בנייה (כמו התראות או רכישות), משנים אייקון, שם או הרשאות.
1. מעלים את המספר `version` ב-`app.json` (למשל מ-`1.0.0` ל-`1.1.0`).
2. בונים ושולחים כמו בשלב 8.
3. עדכון מהיר ששלחתם לגרסה הישנה לא מגיע לגרסה החדשה, ולהפך. ככה אף טלפון לא מקבל קוד שלא מתאים לו.

**בכל עדכון:**
- מעלים את המספר של "מה חדש" במשחק (`src/data/news.ts`) וכותבים מה השתנה, כדי שהשחקנים יראו.
- שומרים על השמירות של השחקנים: אני מוסיף "המרה" לשמירה הישנה בכל שינוי, וזה נבדק בבדיקות.
- אם עדכון מהיר יצא עם בעיה: `eas update:rollback` מחזיר את הקודם.

# SiteFlow – מדריך לפיילוט

יש שתי דרכים להתחיל. אפשר להתחיל בדרך א' מחר בבוקר ולעבור לדרך ב' אחר כך, בלי להקליד שוב כלום.

| | א'. מחשב נייד (מצב הדגמה) | ב'. ענן (Supabase + Vercel) |
|---|---|---|
| זמן הקמה | כ-10 דקות | שעה-שעתיים, בעיקר פתיחת חשבונות |
| מי יכול להשתמש | רק מי שיושב מול המחשב | כולם, מכל טלפון |
| כניסה | בחירת משתמש מרשימה, בלי סיסמה | אימייל, או SMS לטלפון |
| קבלנים מקבלים הודעות | לא | כן (באפליקציה ובהתראות לטלפון) |
| מתאים ל | פגישת הקמה עם מנהל הפרויקט | פיילוט אמיתי באתר |

## א'. על מחשב נייד, למחר בבוקר

1. מתקינים [Node.js](https://nodejs.org) בגרסה 20 ומעלה.
2. מורידים את הקוד ומריצים:
   ```bash
   npm install
   npm run build
   npm start
   ```
3. פותחים בדפדפן `http://localhost:3000`, נכנסים כ**רפאל כהן (מנהל פרויקט)**, ובתפריט המשתמש (העיגול עם ראשי התיבות) בוחרים **פרויקט חדש**.
4. רשות: כדי שהצ'אט וה"שאל את הפרויקט" יעבדו עם AI, יוצרים קובץ `.env.local` עם השורה `ANTHROPIC_API_KEY=...`. בלי מפתח עובד מנתח פשוט יותר.

כל הנתונים נשמרים בקובץ `.data/demo-db.json`. **כדאי לגבות אותו** בסוף הפגישה. הכפתור "אפס נתוני הדגמה" במסך הכניסה מוחק אותו.

## יש כבר תוכנית עבודה באקסל / גוגל שיטס?

1. בגוגל שיטס: **קובץ ← הורדה ← Microsoft Excel (.xlsx)**.
2. באפליקציה: **פרויקט חדש**, מסמנים "יש לי תוכנית עבודה באקסל", ואחרי הפתיחה מעלים את הקובץ ב**הגדרות ← פרויקט ← ייבוא תוכנית עבודה מאקסל**.
3. לפני הייבוא רואים מה נמצא: כמה משימות ואנשי קשר, וכל התלויות בשמות המשימות. אם התלויות לא הגיוניות (למשל המספרים לא עודכנו אחרי מיון), מבטלים את "ייבא גם את התלויות".
4. משימות שסומנו "הושלם" בגיליון ועוד לא נבדקו מגיעות ל**אישורים** וממתינות לאישור שלך. משימות "חסום" נכנסות כחסומות עם הסיבה.
5. כשהגיליון מתעדכן, מעלים אותו שוב. אותן משימות מתעדכנות ולא נוצרות פעמיים, ותלויות שנמחקו מהגיליון נמחקות גם באפליקציה.

מהמחשב אפשר לבדוק קובץ לפני ייבוא עם `npm run inspect-plan -- plan.xlsx`.

## סדר העבודה בפגישה עם מנהל הפרויקט (כשעה)

1. **פרויקט חדש:** שם, כתובת, תאריכים ומבנה הבניין (מאיזו קומה עד איזו, כמה דירות בקומה, מספר הדירה הראשונה). מסמנים גם מה יש בבניין (חניון, מעלית, ספרינקלרים), והאם יש דירות גן בקומה התחתונה ומכפילים בקומה העליונה. כמה בניינים? מוסיפים עוד בניין ב**הגדרות ← פרויקט ← הוסף בניין / קומות**.
2. **קבלנים:** ב**הגדרות ← קבלנים ← ייבוא רשימת קבלנים** מדביקים שורה לכל קבלן: `שם, מקצוע, טלפון`. אפשר להדביק ישר מאקסל או מוואטסאפ.
3. **התהליך:** ב**תרשים זרימה** יש שני תהליכים:
   - **דירות:** סדר העבודות בתוך כל דירה. בכפתור **סוג דירות** מסמנים דירות גן ומכפילים, והן מקבלות שלבים משלהן (חצר, מדרגות פנימיות).
   - **חלקים משותפים:** גג ודודי שמש, חדר מדרגות, לובי ודלת כניסה, מעלית, חניון, ספרינקלרים, חזיתות ופיתוח, לכל בניין. בכפתור **מה יש בבניין** מסמנים חניון, מעלית וספרינקלרים, והשלבים של מה שאין לא ייווצרו.

   התהליכים מקושרים ביניהם. למשל, ריצוף חצר בדירת גן מחכה לפירוק הפיגומים, וחיבור המים החמים בדירה מחכה להתקנת הדודים על הגג.
   ב**עריכת התהליך** עוברים יחד על השלבים ומתקנים לפי איך שהם עובדים בפועל: סדר, שלבים חסרים, זמני ייבוש.
4. **קליטת מצב קיים:** ב**תרשים זרימה ← לוח דירות ← קליטת מצב קיים** בוחרים קומה או דירות ו"בוצע עד" שלב מסוים. השלבים שנשארו מתוזמנים מחדש מהיום. זה לא שולח שום הודעה לקבלנים. אותו דבר עושים ב**חלקים משותפים ← לוח בניינים** לכל בניין.
5. **שיוך קבלנים:** ב**לוח דירות ← שיוך קבלנים** בוחרים קבלן לכל מקצוע, למשל "כל הטיח ← סאמר", בכל הדירות או רק בחלק מהן. ליד כל מקצוע מוצג כמה משימות עוד בלי קבלן.
6. **חריגים:** כפתור **סימון מהיר** בלוח הדירות. לחיצה על משבצת הופכת אותה לבוצע או לא בוצע.
7. **בדיקה:** במסך **מה אפשר לבצע עכשיו** ובלוח הדירות, מנהל הפרויקט מאשר שזה באמת המצב באתר.
8. **הפעלה:** רק בענן, כשהכול נכון, לוחצים **הפעל הודעות לקבלנים**. עד אז הפרויקט ב"מצב הקמה": אין הודעות ואין תזכורות לקבלנים.

בדף הבית של פרויקט חדש מופיעה רשימת "הקמת הפרויקט" שמראה מה כבר נעשה.

## ב'. העלאה לענן (פיילוט אמיתי)

### 1. Supabase (מסד נתונים, כניסה, קבצים)
1. פותחים פרויקט ב-[supabase.com](https://supabase.com). אזור קרוב לישראל, למשל אירופה.
2. ב-**Database ← Extensions** מפעילים את `pg_cron` ואת `pg_net` (בשביל התזכורות).
3. מריצים את כל הקבצים שבתיקייה `supabase/migrations/` לפי הסדר: עם `supabase link` ואז `supabase db push`, או בהדבקה לעורך ה-SQL קובץ אחרי קובץ.
4. **כניסה באימייל** עובדת מיד. **כניסה ב-SMS** (מה שהקבלנים צריכים) דורשת ספק SMS, למשל Twilio, ב-**Authentication ← Providers ← Phone**.
5. ב-**Authentication ← URL Configuration** מגדירים את כתובת האפליקציה ב-Site URL, ומוסיפים את `https://<הכתובת>/auth/callback` ל-Redirect URLs.

### 2. Vercel (השרת)
מייבאים את המאגר ב-[vercel.com](https://vercel.com) ומגדירים את משתני הסביבה:

| משתנה | מאיפה |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase ← Project Settings ← API |
| `SUPABASE_SERVICE_ROLE_KEY` | אותו מקום. **סודי** |
| `SITEFLOW_ADMINS` | האימייל של מי שפותח את הפרויקט, למשל `pm@company.co.il` |
| `CRON_SECRET` | מחרוזת אקראית ארוכה |
| `ANTHROPIC_API_KEY` | [console.anthropic.com](https://console.anthropic.com) (בשביל ה-AI) |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | `npm run gen:vapid` (התראות לטלפון) |

בענן חייבים את Supabase. מצב הדגמה לא שומר נתונים בשרת כזה.

### 3. תזכורות
בעורך ה-SQL של Supabase מריצים פעם אחת:
```sql
select public.siteflow_schedule_tick('https://<כתובת-האפליקציה>', '<CRON_SECRET>');
```

### 4. כניסה ראשונה
מנהל הפרויקט נכנס עם האימייל שהוגדר ב-`SITEFLOW_ADMINS` ומגיע ישר למסך "פרויקט חדש". קבלנים שנוספו עם מספר טלפון מקבלים גישה אוטומטית ברגע שהם נכנסים עם אותו מספר.

### 5. העברת פרויקט מהמחשב הנייד לענן
מהמחשב שעליו הוזנו הנתונים, עם `NEXT_PUBLIC_SUPABASE_URL` ו-`SUPABASE_SERVICE_ROLE_KEY` בקובץ `.env.local`:
```bash
npm run push-project -- --project "שם הפרויקט" --pm-email pm@company.co.il --company "שם החברה"
```
הסקריפט מעביר את המבנה, הקבלנים, המשימות, התלויות, השלבים שסומנו כבוצעו והתהליך המותאם. הפרויקט נכנס לענן במצב הקמה. אפשר להוסיף `--dry-run` כדי לראות קודם מה יועבר. היסטוריית הצ'אט לא מועברת.

> לא מריצים `npm run seed` על מסד הנתונים של הפיילוט: הוא מוסיף את פרויקט ההדגמה.

## מה עוד לא קיים
- **וואטסאפ:** הקוד מוכן, צריך לחבר חשבון של Meta (ראו docs/WHATSAPP.he.md). עד אז הקבלנים מקבלים הודעות באפליקציה ובהתראות לטלפון. באייפון ההתראות עובדות רק אחרי "הוספה למסך הבית".
- **כניסה ב-SMS:** דורשת ספק SMS (סעיף 1.4).

## מה לבקש ממנהל הפרויקט לפני הפגישה
1. כמה בניינים, קומות ודירות בכל קומה.
2. רשימת קבלנים: שם, מקצוע, טלפון.
3. איפה כל דירה עומדת. מספיק צילום של הטבלה או הלוח שהוא כבר מנהל.
4. תוכניות PDF של הקומות, אם יש.

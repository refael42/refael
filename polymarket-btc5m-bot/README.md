# בוט Polymarket – ביטקוין 5 דקות, לפי הרוב

הבוט סוחר בשווקי **"Bitcoin Up or Down – 5 minute"** של Polymarket.
בכל חלון של 5 דקות הוא:

1. מחכה `ENTRY_SECOND` שניות מתחילת החלון (ברירת מחדל: 120).
2. בודק בספר הפקודות מה הרוב חושב: המחיר של Up או Down הוא ההסתברות שהשוק נותן לכיוון (Up ב־0.72 = ‏72% מהשוק חושבים שהביטקוין יסיים את החלון גבוה יותר).
3. אם הרוב חזק מספיק (`MIN_CONFIDENCE`) והמחיר לא יקר מדי (`MAX_ENTRY_PRICE`), קונה את הצד של הרוב בסכום של **x מהכסף** לפי הנוסחה שבחרת.
4. אחרי שהשוק נסגר, רושם רווח/הפסד, ואם יש מפתח Relayer, גם פודה את הזכייה חזרה ליתרה.

יש שני מצבים: **paper** (ברירת מחדל: כסף מדומה מול השוק האמיתי, שום פקודה לא נשלחת) ו־**live** (כסף אמיתי).

## ⚠️ קודם כל: מה הנתונים אומרים

הרצתי את האסטרטגיה על **2,016 חלונות אמיתיים (7 ימים, 20–27 באוקטובר 2026)** עם העמלות והמחירים האמיתיים של Polymarket, בהימור קבוע של $1:

| כניסה אחרי | הימורים | הרוב צדק | מחיר ממוצע ששולם | תשואה |
|---|---|---|---|---|
| 0 שניות | 111 | 69.4% | 74.7% | ‎-8.8%‎ |
| 60 שניות | 890 | 78.8% | 79.9% | ‎-2.8%‎ |
| 120 שניות | 1,044 | 83.3% | 83.1% | ‎-0.9%‎ |
| 180 שניות | 930 | 82.7% | 84.7% | ‎-3.6%‎ |
| 240 שניות | 516 | 86.8% | 86.2% | ‎-0.3%‎ |

(עם `MIN_CONFIDENCE=0.70`, `MAX_ENTRY_PRICE=0.95`. גם בשילובים אחרים שבדקתי, 0.50–0.80, יצא הפסד כמעט בכל שורה.)

**המשמעות:** הרוב אכן צודק ברוב הפעמים, אבל משלמים על זה בדיוק. כשהרוב צודק ב־83% מהמקרים, המניה עולה 83 סנט. בלי יתרון אמיתי על השוק, התוצאה היא בערך אפס, ואז העמלה (כ־3.5% מהסכום כשהמחיר 50 סנט, כ־1.2% כשהוא 83 סנט) ומרווח הקנייה הופכים אותה להפסד קבוע. הבוט עושה בדיוק מה שביקשת, אבל לפי הנתונים האלה **הוא צפוי להפסיד לאט**, לא להרוויח.

אפשר לבדוק את זה בעצמך על הנתונים העדכניים ביותר, בכל רגע:

```bash
python -m bot backtest --hours 168 --flat
```

## שימוש

```bash
python -m bot check      # בודק חיבור, מיקום ויתרה, ומראה מה הבוט היה עושה עכשיו
python -m bot backtest   # מריץ את ההגדרות שלך על 48 השעות האחרונות (--hours 168 לשבוע)
python -m bot run        # מפעיל את הבוט (paper או live לפי MODE ב־.env)
python -m bot stats      # סיכום ההימורים עד עכשיו
```

הבוט צריך לרוץ ברציפות, כלומר מחשב שנשאר דלוק או שרת קטן (VPS). עוצרים אותו עם Ctrl+C, וכשמפעילים אותו מחדש הוא ממשיך מאיפה שעצר.

כל ההימורים נשמרים ב־`data/paper-trades.csv` / `data/live-trades.csv` (אפשר לפתוח באקסל), והלוג ב־`data/*-bot.log`. עשיית השוק שומרת בקבצים נפרדים (`data/paper-mm-trades.csv` וכו').

**מומלץ מאוד:** להריץ קודם במצב paper לפחות כמה ימים ולראות מה `stats` מראה.

## הנוסחה: כמה כסף בכל פעם ("x")

ב־`.env`:

| `STAKE_FORMULA` | כמה מהמרים |
|---|---|
| `fraction` | ‏`BET_FRACTION` מהיתרה בכל פעם (0.02 = 2%) |
| `confidence` | ‏`BET_FRACTION × (מחיר הרוב − 0.5) × 2`: יותר כשהרוב חד יותר. רוב של 75% ← חצי מ־BET_FRACTION, רוב של 95% ← ‏90% ממנו |
| `fixed` | ‏`FIXED_BET_USD` דולר בכל פעם |

אחרי הנוסחה: לא יותר מ־`MAX_BET_USD`, ואם יוצא פחות מ־`MIN_BET_USD` מדלגים על החלון.
כדי להוסיף נוסחה משלך: הפונקציה `stake_for` ב־`bot/strategy.py`.

## מצב עשיית שוק (`STRATEGY=market_maker`)

במצב הזה הבוט לא מהמר על כיוון. בכל חלון, משנייה `MM_START_SECOND` עד `MM_STOP_SECOND`, הוא:

1. שם הצעות קנייה מוגבלות (limit) גם על Up וגם על Down, כל אחת `MM_HALF_SPREAD` מתחת למחיר ההוגן. ההצעות תמיד מתחת למחיר המכירה הזול ביותר בספר, כך שהן ממתינות בספר כפקודות maker ולא משלמות עמלה.
2. מעדכן את המחירים כל `MM_REFRESH_SECONDS` שניות.
3. מנסה לצבור **זוגות**: מניית Up ומניית Down ביחד משלמות תמיד בדיוק $1. זוג שנקנה ב־97 סנט מרוויח 3 סנט, לא משנה מי מנצח.
4. אם צבר יותר מדי מצד אחד, מוריד את ההצעה בצד הזה ומעלה בצד השני (`MM_SKEW_PER_SHARE`), ועוצר לגמרי ב־`MM_MAX_IMBALANCE_SHARES`.
5. מפסיק להציע כשהחלון כבר מוכרע (`MM_MIN_PRICE`) או כשהגיע לתקרת ההוצאה לחלון (`MM_MAX_SPEND_PER_WINDOW`).

```bash
STRATEGY=market_maker python -m bot backtest --hours 48 --grid           # שמרני
STRATEGY=market_maker python -m bot backtest --hours 48 --grid --touch   # אופטימי
```

### ⚠️ התוצאות: מפסיד במהירות של הבוט הזה

**מחיר הוגן מהמחיר של פולימרקט** (`MM_FAIR_SOURCE=market`):

- **בדיקה על 576 חלונות (48 שעות):** כל 12 ההגדרות הפסידו, ‎-2.4%‎ עד ‎-5.2%‎.
- **תרגול חי (12:15–13:30 UTC, 27.10):** ‎-6.9%‎.
- **הסיבה:** המחיר זז 10 סנט ויותר בתוך שתי שניות, וההצעות של הבוט מתמלאות בעיקר בצד שעומד להפסיד.

**מחיר הוגן ממחיר הביטקוין** (`MM_FAIR_SOURCE=btc`, ברירת המחדל, `bot/fair.py`):

- **המודל:** מחשב בכל שנייה את ההסתברות ל־Up ממחיר הביטקוין בבינאנס, לפי חוק ההכרעה (ממוצע 60 השניות שלפני הפתיחה מול ממוצע 60 השניות האחרונות).
- **שחזור התוצאות:** הוא משחזר את התוצאה האמיתית ב־98.4% מהחלונות.
- **דיוק:** הוא לא מנבא את התוצאה טוב יותר מהשוק.
- **המהירות:** הוא רואה תנועה של הביטקוין לפני שהמחיר בפולימרקט מגיב. השוק סוגר כ־28% מהפער בתוך 5 שניות.
- **בבדיקה על ההיסטוריה:** ‎+1.6%‎ (שמרני) ו־‎+4.8%‎ (אופטימי).
- **בתרגול חי (16:35–18:05 UTC, 27.10):** 13 חלונות נסגרו, הבוט הוציא $257 והפסיד ‎$12.37 ‏(‎-4.8%‎).

**למה הבדיקה הייתה אופטימית:** היא עובדת ברמת שנייה, ומניחה שהבוט מעדכן הצעות מיד אחרי תנועה של הביטקוין. אותה בדיקה עם עיכוב תגובה (600 חלונות, 50 שעות, `MM_HALF_SPREAD=0.05`):

| עיכוב תגובה | שמרני | אופטימי |
|---|---|---|
| 0 שניות | ‎+1.6%‎ | ‎+4.5%‎ |
| שנייה | ‎-1.4%‎ | ‎+0.8%‎ |
| 2 שניות | ‎-5.1%‎ | ‎-3.0%‎ |
| 3 שניות | ‎-6.0%‎ | ‎-4.5%‎ |

התרגול החי (‎-4.8%‎) מתאים לעיכוב של כ־2 שניות. זו המהירות האמיתית של בוט כזה: עדכון כל 1–2 שניות, ועוד זמן רשת. היתרון של המודל קיים רק בתגובה של פחות משנייה. בשביל זה צריך זרם מחירים מהיר יותר (פולימרקט מעבירה מחיר פעם בשנייה) וחיבור קרוב לשרתים. כנראה זה מה שעושי השוק המקצועיים שם עושים.

**במצב live:**
- **פקודות post-only:** פקודה שהייתה מתבצעת מיד נדחית, כך שלא משלמים עמלה.
- **heartbeat:** הבוט שולח לפולימרקט אות חיים כל 4 שניות. אם הוא נופל, פולימרקט מבטלת תוך כ־10 שניות **את כל** הפקודות הפתוחות של מפתח ה־API הזה.
- **פקודות עם תפוגה:** כל פקודה פגה מעצמה אחרי כמה דקות.
- **התאמה מול ההיסטוריה:** אחרי כל חלון הבוט מתקן את הרישום לפי היסטוריית העסקאות האמיתית בפולימרקט.

## מעבר לכסף אמיתי (live)

1. **מומלץ חשבון Polymarket נפרד** ובו רק סכום שמוכנים להפסיד.
2. ב־`.env`:
   - `MODE=live`
   - `POLYMARKET_WALLET_ADDRESS`: כתובת הארנק מתפריט הפרופיל באתר.
   - `POLYMARKET_PRIVATE_KEY`: המפתח הפרטי של הארנק שאיתו נכנסים לחשבון. בחשבון שנפתח עם מייל או Google אפשר לייצא אותו מהגדרות החשבון באתר. בחשבון MetaMask זה המפתח של אותו ארנק.
   - (רשות) `POLYMARKET_RELAYER_API_KEY` + `POLYMARKET_RELAYER_API_KEY_ADDRESS`: מ־Settings → API Keys → Relayer API Keys. איתם הבוט פודה זכיות לבד. בלעדיהם צריך ללחוץ Claim באתר, ועד אז הכסף מהזכיות לא חוזר ליתרה שהבוט רואה.
3. `python -m bot check`: לוודא שהארנק, היתרה והמיקום תקינים.
4. `python -m bot run`.

**אבטחה:** המפתח הפרטי נותן שליטה מלאה בכסף בחשבון. הוא נשמר רק בקובץ `.env` על המחשב שלך (הקובץ ב־`.gitignore`). לא לשתף אותו ולא להעלות אותו לשום מקום.

**מיקום:** Polymarket חוסמת פקודות מחלק מהמדינות (למשל ארה"ב, בריטניה, צרפת, גרמניה ואוסטרליה). הבוט בודק את זה בהפעלה במצב live ולא ישלח פקודות ממיקום חסום.

## הגנות מובנות

- `MAX_BET_USD`: תקרה לכל הימור.
- `MAX_DAILY_LOSS_USD`: אחרי הפסד כזה ביום, הבוט מפסיק להמר עד מחר.
- `STOP_BELOW_BALANCE_USD`: עוצר כשהיתרה יורדת לסכום הזה.
- `MAX_ENTRY_PRICE` + `SLIPPAGE`: פקודת השוק לא תתמלא מעל מחיר מקסימלי.
- הימור אחד לכל היותר בכל חלון, גם אחרי הפעלה מחדש.

```
bot/strategy.py   ההחלטה: הצד של הרוב, הנוסחה, עמלות (בלי רשת, עם בדיקות)
bot/market.py     מציאת השוק של החלון הנוכחי וקריאת ספר הפקודות
bot/broker.py     paper (סימולציה) / live (פקודות אמיתיות דרך ה־SDK הרשמי)
bot/runner.py     הלולאה: כניסה, סגירה, פדיון, הגנות
bot/ledger.py     רישום ההימורים (JSON + CSV)
bot/backtest.py   הרצה על היסטוריה אמיתית
bot/mm.py         עשיית שוק: איפה להציע, מלאי, כלל המילוי (בלי רשת, עם בדיקות)
bot/maker.py      פקודות עשיית שוק: paper (מול זרם העסקאות החי) / live
bot/mm_runner.py  הלולאה של עשיית השוק
bot/mm_backtest.py  הרצת עשיית השוק על עסקאות אמיתיות מהעבר
tests/            python -m unittest discover -s tests -t .
```

הבוט משתמש ב־SDK הרשמי של Polymarket ‏(`polymarket-client`). הוא עובד גם עם שווקי 5 דקות של מטבעות אחרים, אם יש כאלה. משנים את `MARKET_PREFIX`, למשל `eth-updown-5m`.
